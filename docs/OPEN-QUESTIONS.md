# Open Questions

The source spec leaves these ambiguous. Each has a **proposed default** so work can proceed. The project owner may override any default; when that happens, record the change in DECISIONS.md.

| ID | Question | Proposed default |
|---|---|---|
| OQ-01 | **Simultaneous vs. alternating turns.** The spec asks for simultaneous planning but also wants "first-turn advantage" analytics, and classic team battlers alternate. | Build the resolver so both work: a `TurnModel` config with `simultaneous` (default) and `alternating`. Under simultaneous play, "first-turn advantage" is measured as the initiative-holder's advantage (OQ-02). |
| OQ-02 | Within the same resolution tier, whose action resolves first? | Initiative alternates each turn (a coin-flip seeded from RNG decides turn 1). Within a player, order follows the ally slot (1→3). Always deterministic and shown in the UI. |
| OQ-03 | Default energy generation. | 1 random energy per living character per turn, with a pool cap of 10 per type, full carryover, and no energy on turn 1 for the initiative player. All values configurable. |
| OQ-04 | Does life transfer (Borrowed Life) bypass anti-heal or "cannot be healed" (Behemoth)? | Healing has classes: `heal`, `lifeTransfer`, `setHp`. Anti-Heal and Behemoth's passive block `heal` only; Healing Reduction affects both `heal` and `lifeTransfer`. Log the decision. |
| OQ-05 | Legends are stronger and unlocked by accomplishment. How should they work in local ranked and friend matches? | Local ranked: bots in lower divisions use at most 1 Legend per team; the player may use any Legends they've unlocked. Friend matches: the host chooses "own unlocks" or "everything unlocked" with an optional max-1-Legend rule. Revisit at Phase 11 using simulation data. |
| OQ-06 | **Nameless One rewind semantics.** | When he would die, restore the full snapshot from the start of the current turn (both teams). The same actions do not replay; both players re-plan. The RNG stream advances (no identical re-roll). Once per battle, and consumed even if the rewound turn kills him again. |
| OQ-07 | Behavior when a Cheater changes targets "after selection" under simultaneous planning. | Implement retargeting as a Priority-tier effect that modifies queued actions, and log the change. |
| OQ-08 | Timer expiry with no lock-in. | Unlocked actions are dropped (character passes). In friend matches, the timer is advisory, since async turns have no shared clock; a player may resign or abandon. In local ranked against bots, the timer is optional in settings. |
| OQ-09 | Simultaneous team wipe. | Draw. In ranked, a draw counts as neither a win nor a loss, with a small MMR adjustment toward parity. |
| OQ-10 | **"MICHELIN MONSTER" uses a registered trademark.** | Rename before shipping (e.g., "The Five-Star Fiend", "Grand Kitchen Horror"). Use the placeholder id `chef-ramble.monster`. |
| OQ-11 | "Devourer of Worlds" has a well-known comic-book association. | Low risk as a generic phrase; flag it for legal review before launch. |
| OQ-12 | "Each culture must receive specific research before final visual production." Claude Code cannot substitute for cultural consultants. | Art specs are marked `status: draft`. Final production requires human review, ideally by people from those cultures. |
| OQ-13 | Hidden mechanics vs. ranked integrity. | Every effect that changes state emits a log event, even hidden ones; the event text may be cryptic but must exist. Codex entries unlock from the player's own event history. |
| OQ-14 | Maximum match length. | 40 turns; then the team with the higher total remaining HP percentage wins; if tied, draw. |
| OQ-15 | Mirror matches / duplicate characters. | No duplicates within a team; mirrors across teams are allowed. |
| OQ-16 | Players can edit local saves to unlock everything. | Accepted (ADR-002). Keep the checksum to detect accidental corruption only, and do not attempt obfuscation-based anti-cheat. |
| OQ-17 | Saves from older builds after balance/content changes. | Saves store IDs and progress, never character numbers. Migrations handle renamed or removed IDs. Every shipped BalanceVersion stays in the build for replays. |
| OQ-18 | Live WebRTC needs STUN/TURN servers to cross most home networks. | Stretch goal only, LAN-guaranteed. Public STUN is optional and off by default; code matches are the supported path. |
| OQ-19 | Browsers may evict IndexedDB data under storage pressure (especially Safari's ~7-day rule for non-installed sites). | The primary mitigation is installing as an app early, plus `storage.persist()`, rolling backups, and an easy QR transfer and share-sheet backup. |
| OQ-20 | Hosting. | Static host of the owner's choice. Also produce an optional single-file build for local/offline distribution. |
| OQ-21 | Art assets without an image API at runtime. | Art is produced offline from the CharacterArtSpecs and shipped as static, optimized images (WebP/AVIF) with lazy loading by region. Generated placeholder portraits are used until then. |
| OQ-22 | On iOS, installed home-screen apps have separate storage from Safari, and links/camera scans open Safari rather than the app. | Prompt install before real play; offer "Move my progress into the app"; iOS transfers use the in-app scanner or paste, not links. |
| OQ-23 | The transfer payload could outgrow a single QR code as content expands. | Budget ≤ 2,500 bytes compressed, tested against a maxed profile. The fallback is an animated multi-frame QR sequence, then the share-sheet file. |
| OQ-24 | A service-worker update could break an old save. | Migrations run before any save write in a new version, and the rolling backup is taken before migrating. |
| OQ-25 | Phase 00 requires zod schemas for `BattleState`, but full per-character runtime fields (HP, active statuses, cooldowns, live resource values) depend on the resolver design, which is explicitly out of scope for Phase 00. | Ship `BattleState` as a foundational skeleton now (format, teams, RNG state, energy pools, event log) and extend it with per-character runtime state in Phase 01 when the resolver is built. This is additive, not a breaking change, since Phase 00 ships no persisted battle states yet. |
| OQ-26 | ~~`apps/web/index.html`'s strict CSP meta tag was unverified against Vite's dev server (HMR websocket, eval-based dev tooling).~~ **Resolved 2026-09-17:** verified in the browser pane against both `vite dev` and `vite preview` (the production build) — the app renders, `document.title` updates to `GAME_TITLE`, HMR's websocket connects, and no CSP violations appear in the console. | No dev-only relaxation needed; the CSP as written works in both modes. |
